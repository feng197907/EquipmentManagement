## 0. 先搞清三个地方

上线这件事，本质上就是**让同一份代码出现在三个地方**，而且顺序不能乱。

| 位置 | 是什么 | 你在这里做什么 |
|---|---|---|
| **本地** `D:\EquipmentManagement` | 你写代码的地方 | 改代码、提交、推到 GitHub |
| **GitHub** `feng197907/EquipmentManagement` | 中转站，存所有历史版本 | 不用手动操作，`git push` 会自动送上去 |
| **服务器** `/data/EquipmentManagement` | 对外提供服务的那台（101.201.48.64） | 把代码拉下来、重建镜像、换容器 |

三者的关系：

```
  你的电脑                      GitHub                    阿里云服务器
 D:\EquipmentManagement  ──push──▶  远程仓库  ──pull──▶  /data/EquipmentManagement
        (改代码)                  (存档+中转)              (运行 docker 容器)
                                                                  │
                                                          nginx :80/:443
                                                                  │
                                                          用户手机/电脑访问
```

**关键认知**：你在本地保存文件，线上是什么都不会变的。必须走完「推送 → 服务器拉取 → 重建镜像」三步，用户才能看到。

## 1. 本地：把改动提交上去

打开 **Git Bash**（开始菜单搜索 Git Bash），然后进入项目目录：

```bash
cd /d/EquipmentManagement
```

> Git Bash 里 `D:\EquipmentManagement` 要写成 `/d/EquipmentManagement`（斜杠方向反过来，盘符小写）。
> 后面所有命令都假设你已经在这个目录里了，不用每次都 `cd`。

### 1.1 先看清自己改了什么

改动之前先确认范围，避免把不该提交的东西（数据库文件、日志、密钥）带上去。

```bash
git status --short
```

**✅ 看到什么算对**

- 每行以 ` M`（修改）或 `??`（新增未跟踪）开头，后面是文件路径
- 如果出现 `.env`、`*.db`、`logs/`、`uploads/` —— **不正常**，说明 `.gitignore` 漏了，先别提交
- 如果一行都没有，说明你没改任何文件

再看具体的改动量：

```bash
git diff --stat
```

**✅ 看到什么算对**

```
 static/css/components.css | 41 +++++++++++++++++++++--------------
 templates/reminders.html  |  2 +-
 2 files changed, 28 insertions(+), 15 deletions(-)
```

确认这些都是你想上线的改动，再往下走。

### 1.2 本地跑一下看看（建议，不是必须）

改了界面或逻辑，先在本地起一遍，别拿线上做实验。

```bash
py -3 app.py
```

**✅ 看到什么算对**

终端最后出现 `Running on http://127.0.0.1:5000`，浏览器打开这个地址能看到页面。

看完按 `Ctrl + C` 停掉。

### 1.3 改了 CSS / JS？先把版本号提一下

**这一步最容易被忘，忘了的后果是：你自己看到的是新样式，用户看到的还是旧的。**

浏览器会把 CSS 缓存起来，只要文件名（URL）没变就不重新下载。项目用 `?v=数字` 这个查询参数当缓存开关，改了样式就必须把这个数字 +1。

先看现在是多少：

```bash
grep -rn "?v=" templates/ | head
```

**✅ 看到什么算对**

```
templates/base.html:18:  ...css/variables.css?v=6" rel="stylesheet">
templates/login.html:16: ...css/variables.css?v=6" rel="stylesheet">
```

所有行都是**同一个数字**（当前是 `6`）。如果有的大有的小，说明上次漏改了，一起统一掉。

把 `6` 改成 `7`（如果已经是 7 就改成 8，总之比线上大）：

```bash
py -3 -c "import glob,io; [io.open(p,'w',encoding='utf-8',newline='').write(io.open(p,encoding='utf-8').read().replace('?v=6','?v=7')) for p in glob.glob('templates/*.html')]"
```

**✅ 看到什么算对**

再跑一次 `grep -rn "?v=" templates/ | head`，数字全变成 `7`，没有残留的 `6`：

```bash
grep -rn "?v=6" templates/
```

```
（什么都不输出 = 干净）
```

### 1.4 提交

```bash
git add -A
git commit -m "fix(reminders): 修复筛选徽标数字看不清"
```

**✅ 看到什么算对**

```
[main 403d71a] fix(reminders): 修复筛选徽标数字看不清
 6 files changed, 42 insertions(+), 29 deletions(-)
```

方括号里的 `403d71a` 就是这次提交的版本号，**记下来**，回滚时要靠它。

需要写详细说明（推荐，将来查问题时能看懂当时为什么改）：

```bash
git commit -F - <<'EOF'
fix(css): 修复按钮内徽标文字被强制 inherit 导致数字看不见

根因：.btn span 规则把徽标也算进去了，白字压白底，对比度 1.05:1。
修法：13 条规则统一加 :not(.badge)，并补上 .badge-light 定义。
EOF
```

### 1.5 推到 GitHub

```bash
git push origin main
```

**✅ 看到什么算对**

```
To github.com:feng197907/EquipmentManagement.git
   6ab3a8d..403d71a  main -> main
```

看到 `main -> main` 就成了。如果报 `rejected` 或 `non-fast-forward`，说明 GitHub 上有你本地没有的提交，先 `git pull --rebase origin main` 再推。

> 用 GitHub Desktop 的话，等价操作是点 **Commit to main**，再点 **Push origin**。

**到这一步，本地的事情就做完了。** 线上此刻还没变。

## 2. Docker 在这里到底干什么

### 2.1 三个词，一个比喻

| 词 | 比喻 | 在这个项目里 |
|---|---|---|
| **镜像 image** | 一张装好系统的安装盘 | `equipment-management:latest`，里面是你的代码 + Python + 依赖 |
| **容器 container** | 用安装盘装出来的一台机器 | `dms-app`，正在跑的那台 |
| **compose** | 一张装机单，写清楚怎么装 | `docker-compose.yml`，规定了端口、挂载目录、重启策略 |

**最重要的推论**：改了代码 = 安装盘里的内容变了 → **必须重新做盘（build），再用新盘重装（up -d）**。

### 2.2 这个项目里，哪些在容器里

| 组件 | 跑在哪 | 说明 |
|---|---|---|
| Flask 应用 (gunicorn) | **容器 `dms-app`** | 唯一容器化的东西，监听 127.0.0.1:5000 |
| nginx | 宿主机 | 负责 80/443，把请求转给 5000 |
| MariaDB | 宿主机 | 数据库，只监听 127.0.0.1:3306 |

容器用的是 `network_mode: host`（共用宿主机网络），所以容器里的 `127.0.0.1` 就是宿主机的 `127.0.0.1`，它能直接连到宿主机上的数据库。**这也是为什么改完容器不用动 nginx** —— nginx 转发的地址一直是 `127.0.0.1:5000`，没变过。

两个目录挂载在宿主机上，容器删了重建数据也不丢：

| 宿主机目录 | 容器内 | 装什么 |
|---|---|---|
| `/data/EquipmentManagement/uploads` | `/app/uploads` | 用户上传的文档 |
| `/data/EquipmentManagement/logs` | `/app/logs` | 应用日志 |

### 2.3 你只需要记住这六条

在服务器上、项目目录里执行：

```bash
docker compose ps
```
看容器在不在、什么状态。

```bash
docker compose build
```
**重做安装盘**（用当前目录的代码）。改了代码必须先跑这个。

```bash
docker compose up -d
```
**用最新的盘重装并后台启动**。镜像变了它会自动换掉旧容器。

```bash
docker compose logs --tail 100 app
```
看最近 100 行应用日志，报错都在这。

```bash
docker compose logs -f app
```
实时跟踪日志，`Ctrl + C` 退出。

```bash
docker compose down
```
停掉并删除容器（数据不丢，因为都在宿主机上）。**日常发布不要用它**，会造成停机。

### 2.4 最大的坑：改了代码只 restart

```bash
docker compose restart      # ← 千万别这么干
```

`restart` 只是把**原来那个容器**重启一遍，镜像没变、代码没变，你改的东西一行都没生效。很多"我明明改了却没反应"都是这么来的。

**正确做法永远是**：

```bash
docker compose build && docker compose up -d
```

或者干脆用第 3 章的一键脚本，它把这两步都包好了。

## 3. 服务器：把代码变成线上

### 3.1 先连上服务器

在本地 Git Bash 里：

```bash
ssh root@101.201.48.64
```

**✅ 看到什么算对**

提示符变成 `[root@iZbpXXXX ~]#` 这样的形式，说明已经进到服务器里了。

然后进项目目录：

```bash
cd /data/EquipmentManagement
```

**✅ 看到什么算对**

```bash
pwd
```
```
/data/EquipmentManagement
```

> 以下所有命令都在**服务器上**执行，直到你 `exit` 退出。
> 密码请从你自己的记录里取，本文档不写密码。

### 3.2 方式 A：一条命令搞定（推荐）

```bash
./deploy/compose-deploy.sh
```

这条命令内部做了四件事：拉代码 → 构建镜像 → 替换容器 → 等健康检查。

**✅ 看到什么算对**

```
== 1/4 拉取最新代码 ==
   当前版本：403d71a fix(css): 修复按钮内徽标文字被强制 inherit 导致数字看不见
== 2/4 构建镜像 ==
...
== 3/4 替换容器 ==
 Container dms-app  Recreated
 Container dms-app  Started
== 4/4 等待健康检查（通常 30~60 秒）==
   [1] starting
   ...
   [17] healthy

发布完成。
  应用探针：200
  对外访问：200
  想再确认一遍：./deploy/status.sh
```

看到 `发布完成` 并且两个数字都是 `200`，就上线成功了。

**如果卡在第 1 步报 `Couldn't connect to server`**，服务器连不上 GitHub —— 跳到 3.4，那是真实发生过的情况。

### 3.3 方式 B：手动分三步（想看清每一步，或脚本出问题时）

```bash
# 第一步：拉取最新代码
git fetch origin
git reset --hard origin/main
git log --oneline -1
```

**✅ 看到什么算对**：最后一行显示的是你本地刚推的那个提交，比如

```
403d71a fix(css): 修复按钮内徽标文字被强制 inherit 导致数字看不见
```

和本地的版本号**必须一致**。不一致说明没拉下来，别往下走。

> 为什么用 `reset --hard` 而不是 `git pull`：部署目录只用来跑服务，不应该有本地改动；
> 而且历史上出现过服务器和本地"内容相同但提交号不同"的情况，`pull` 会因分叉直接报错。
> `reset --hard` 会**丢弃服务器上的本地改动**，所以千万不要在服务器上直接改代码。

```bash
# 第二步：重做镜像
docker compose build
```

**✅ 看到什么算对**：最后几行出现 `naming to docker.io/library/equipment-management:latest` 和 `DONE`。

```bash
# 第三步：换容器
docker compose up -d
```

**✅ 看到什么算对**

```
 Container dms-app  Recreate
 Container dms-app  Recreated
 Container dms-app  Starting
 Container dms-app  Started
```

新代码已经生效了，只是应用还在启动。等 30~60 秒，然后：

```bash
docker inspect --format '{{.State.Health.Status}}' dms-app
```

**✅ 看到什么算对**

```
healthy
```

如果是 `starting`，再等十几秒重试。如果是 `unhealthy`，看日志：

```bash
docker compose logs --tail 100 app
```

### 3.4 方式 C：服务器连不上 GitHub（会真实发生）

**症状**：方式 A/B 的第一步卡住，然后报错

```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com
port 443 after 35896 ms: Couldn't connect to server
```

**原因**：服务器到 github.com 的 443 端口被阻断。注意这条错误**每次要等 36 秒**才报出来，重试也经常一样，不是网络抖动。

**解决办法**：代码已经在 GitHub 上了，那就从**你自己的电脑**直接把代码搬过去，不经过 GitHub。

#### 第 1 步：在服务器上看当前是哪个版本

```bash
cd /data/EquipmentManagement
git log --oneline -1
```

记下这个提交号（比如 `6ab3a8d`），下面叫它 `<旧版本>`。

#### 第 2 步：在本地打一个"增量包"

回到**本地 Git Bash**（不是服务器）：

```bash
cd /d/EquipmentManagement
git bundle create D:/dms-release.bundle <旧版本>..main
```

把 `<旧版本>` 换成刚才记下的号码，例如：

```bash
git bundle create D:/dms-release.bundle 6ab3a8d..main
```

这个包只装了两者之间的差异，通常只有几 KB。

**✅ 看到什么算对**

```
Enumerating objects: 15, done.
...
-rw-r--r-- 1 jm-wtf ... 3062 D:/dms-release.bundle
```

#### 第 3 步：把包传到服务器

用 WinSCP / MobaXterm 这类图形工具，把 `D:\dms-release.bundle` 拖到服务器的 `/tmp/` 目录。

或者用命令行（在 **PowerShell 或 CMD** 里执行，不要在 Git Bash 里）：

```powershell
scp D:\dms-release.bundle root@101.201.48.64:/tmp/
```

> **Git Bash 里执行 scp 会失败**：它会把 `/tmp/` 自动改写成 Windows 路径 `C:/Users/...`，
> 结果文件传到一个不存在的目录。要么用 PowerShell，要么在命令前加 `MSYS_NO_PATHCONV=1`。

#### 第 4 步：在服务器上合入

```bash
cd /data/EquipmentManagement
git fetch /tmp/dms-release.bundle main
git merge --ff-only FETCH_HEAD
git update-ref refs/remotes/origin/main "$(git rev-parse HEAD)"
git log --oneline -1
```

**✅ 看到什么算对**

```
Updating 6ab3a8d..403d71a
Fast-forward
 static/css/components.css | 41 ++++++...
 6 files changed, 42 insertions(+), 29 deletions(-)
403d71a fix(css): 修复按钮内徽标文字被强制 inherit 导致数字看不见
```

**第 3 行那个 `update-ref` 千万别漏。** 它把服务器上"origin/main 指向哪里"这个记录对齐到你刚合入的版本。漏了的话，下次脚本一执行 `reset --hard origin/main`，就会**把刚上线的代码回滚掉**。

#### 第 5 步：跳过拉取，只重建镜像

```bash
./deploy/compose-deploy.sh --skip-fetch
```

`--skip-fetch` 的意思就是"代码我已经弄好了，别去 GitHub 了，直接从构建镜像开始"。

后面和方式 A 完全一样，等到 `发布完成` 即可。

### 3.5 三种方式怎么选

| 情况 | 用哪个 |
|---|---|
| 平时发布 | **方式 A**（一条命令） |
| 想看清每一步 / 方式 A 失败想定位 | **方式 B**（手动三步） |
| 报了 `Failed to connect to github.com port 443` | **方式 C**（bundle 搬运） |


**✅ 逐项对照**

| # | 检查项 | 合格标准 |

| 1 | 代码版本 | 是你要发布的那条提交，工作区"干净" |

## 5. 回滚：上线出问题怎么退回去

假设刚发的 `403d71a` 有问题，要退回上一个版本。

### 第 1 步：找到要退回的版本

```bash
cd /data/EquipmentManagement
git log --oneline -5
```

**✅ 看到什么算对**

```
403d71a fix(css): 修复按钮内徽标文字被强制 inherit 导致数字看不见   ← 有问题的
6ab3a8d fix(mobile): 修复 14 个页面在手机端的横向溢出与折行        ← 退回到这个
53fa2e5 fix(deploy): 给 compose-deploy.sh 补上可执行位
```

### 第 2 步：把代码退回去

```bash
git reset --hard 6ab3a8d
git update-ref refs/remotes/origin/main 6ab3a8d
docker compose build && docker compose up -d
```

或者用脚本：

```bash
git reset --hard 6ab3a8d
git update-ref refs/remotes/origin/main 6ab3a8d
./deploy/compose-deploy.sh --skip-fetch
```

**✅ 看到什么算对**：`./deploy/status.sh` 第 1 项显示的是退回后的提交号，第 3 项 `healthy`。

### 关于数据库

如果这次发布**改了表结构**（加了字段/表），回滚代码**不会**把数据库改回去。多出来的列通常不影响旧代码运行，但如果新代码写了数据到新列，回滚后会"看不到"那部分数据。发布带表结构变更的版本前，先备份数据库：

```bash
cd /data/EquipmentManagement
docker compose exec -T app python -c "print('容器可执行')"   # 确认容器在跑
mysqldump -h 127.0.0.1 -u root -p dms > /root/dms-backup-$(date +%F).sql
```

（把 `dms` 和用户名换成你的实际库名/账号；这条命令会提示输入数据库密码。）

## 6. 改了数据库表结构怎么办

这个项目**没有用 Alembic 之类的迁移工具**，表结构靠 `database.py` 里一份"增量升级清单"在**应用启动时自动执行**。

### 正确做法

改了模型（比如给 `devices` 加一个 `warranty_end` 字段），必须同时在这份清单里加一条：

打开 `database.py`，找到 `_migrate_mysql_columns` 函数，往 `migrations` 列表里追加：

```python
    migrations = [
        # ... 已有的条目 ...

        # 新增：设备保修到期日
        ("devices", "warranty_end",
         "ALTER TABLE devices ADD COLUMN warranty_end DATE DEFAULT NULL"),
    ]
```

格式是 `(表名, 列名, SQL语句)`，脚本会先检查这一列是否存在，不存在才执行，所以**重复执行是安全的**（幂等）。

### 为什么必须加

容器每次启动都会跑一遍这份清单。你不加，线上数据库就**永远不会多出这一列**，然后新代码一查这个字段就报 500。

### 自检清单

发布带表结构变更的版本前，确认：

- [ ] `database.py` 的 `migrations` 里有对应的幂等语句
- [ ] 本地用新库完整跑过一次（`rm dms.db` 之类，或用一个空库）
- [ ] 线上数据库已备份（见第 5 章最后一段）
- [ ] 发布后看日志确认识别到了新列：`docker compose logs --tail 200 app | grep -i "migration"`

## 7. 排错速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 发布完页面完全没变化 | 只 `restart` 没有 `build`，或者拉代码失败但脚本继续跑了 | 重跑 `./deploy/compose-deploy.sh`，确认第 1 步显示的版本号是新的 |
| 样式没变，但代码是新的 | 静态资源版本号没提 | 见 1.3，`?v=` 数字 +1 后重新提交发布 |
| `Failed to connect to github.com port 443` | 服务器到 GitHub 被阻断 | 用方式 C（bundle 搬运） |
| 容器状态 `unhealthy` | 应用起不来或连不上数据库 | `docker compose logs --tail 100 app` 看具体报错 |
| 健康检查一直是 `starting` | 启动慢（首次初始化数据库）或卡在等数据库 | 等 60 秒；仍不行看日志 |
| `docker compose build` 卡在 `apk`/`pip` 下载 | 服务器到 PyPI 慢 | 已配置三个镜像源轮询；重试一次通常能过 |
| `Permission denied` 执行脚本 | 脚本没有可执行位 | `chmod +x deploy/*.sh` |
| `缺少 .env` | 服务器上没有环境变量文件 | `cp .env.example .env` 然后填入真实值 |
| 页面上出现 502 Bad Gateway | 容器没起来，nginx 转不到后端 | `docker compose ps` + `docker compose logs app` |
| 审计日志时间差 8 小时 | 容器缺 tzdata | 镜像里已装 tzdata 并设 `TZ=Asia/Shanghai`，确认没被改掉 |
| 磁盘满了导致数据库挂了 | 日志/镜像堆积 | `docker system df` 看占用，`docker image prune -f` 清旧镜像 |
| 本地 `git push` 被拒 | GitHub 上有你本地没有的提交 | `git pull --rebase origin main` 再推 |

## 8. 命令速查卡

### 本地（Git Bash，`/d/EquipmentManagement`）

```bash
git status --short                 # 改了什么
git diff --stat                    # 改了多少行
grep -rn "?v=" templates/ | head   # 看静态资源版本号
git add -A                         # 全部暂存
git commit -m "说明"                # 提交
git push origin main               # 推到 GitHub
git log --oneline -3               # 最近三个版本
```

### 服务器（`ssh root@101.201.48.64`，`/data/EquipmentManagement`）

```bash
./deploy/compose-deploy.sh                 # 一键发布（含拉代码）
./deploy/compose-deploy.sh --skip-fetch    # 只重建镜像，不拉代码
./deploy/status.sh                         # 上线状态自检（只读）
git log --oneline -1                       # 当前版本
docker compose ps                          # 容器状态
docker compose logs --tail 100 app         # 最近日志
docker compose build                       # 重做镜像
docker compose up -d                       # 换容器
docker inspect --format '{{.State.Health.Status}}' dms-app   # 健康状态
```

### 三个"绝对不要"

1. **不要在服务器上直接改代码** —— 下次 `reset --hard` 会把你的改动抹掉，而且要改两遍。
2. **不要用 `docker compose restart` 代替发布** —— 代码不会生效。
3. **不要把 `.env`、数据库文件、`logs/` 提交进 Git** —— 密钥会泄露到 GitHub。

## 附录 A：新服务器从零到上线

换一台新机器时按这个顺序来，日常上线不需要看这节。

**1. 装 Docker**

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker --version
```

**2. 配国内镜像加速**（否则拉基础镜像会超时）

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1ms.run"]
}
EOF
systemctl restart docker
```

**3. 拉代码**

```bash
mkdir -p /data && cd /data
git clone https://github.com/feng197907/EquipmentManagement.git
cd EquipmentManagement
```

**4. 准备环境变量**

```bash
cp .env.example .env
vi .env          # 填数据库地址、账号、SECRET_KEY
```

**5. 装数据库、建库**

```bash
# 以 MariaDB 为例
dnf install -y mariadb-server && systemctl enable --now mariadb
mysql -u root -e "CREATE DATABASE IF NOT EXISTS dms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

> 表结构不用手动建——容器启动时 `init_db()` 会自己建表并写入默认账号。

**6. 配 nginx 反代到 5000**

`deploy/nginx-http-direct.conf.example` 和 `deploy/nginx-ssl.conf.example` 是现成的配置样例，里面有踩过的坑的注释。

```bash
cp deploy/nginx-http-direct.conf.example /etc/nginx/conf.d/dms.conf
nginx -t && systemctl reload nginx
```

**7. 起容器**

```bash
./deploy/compose-deploy.sh --skip-fetch
./deploy/status.sh
```

**8. 设开机自启**

`docker-compose.yml` 里已经写了 `restart: unless-stopped`，Docker 服务开机自启（第 1 步已 enable），容器就会跟着起来。验证：

```bash
systemctl restart docker && sleep 20
docker compose ps
```
